# Profiling with cloud ops agent

To profile google cloud batch job one can use the implementation of the [Google Cloud Ops Agent](https://cloud.google.com/monitoring/agent/ops-agent)
The agent(s) are installed on the google cloud Virutal Machines. The agents are responsible for collecting telemetry from VMs.

To automatically install **Cloud Ops Agent** to the VM fleet one require the access to the [OS Policy](https://cloud.google.com/compute/vm-manager/docs/os-policies/working-with-os-policies) and [VM manager](https://cloud.google.com/compute/vm-manager/docs/overview).

Once the metrics are collected, then they can be viewed from Google Cloud Monitoring service. See [`CARMA dashboard`](https://console.cloud.google.com/monitoring/dashboards/builder/e87aa472-e2ec-46d0-8218-fea6385f3bfc;filters=type:umlabel,key:benchmark,val:100-sample;startTime=2025-03-17T16:19:39.846Z;endTime=2025-03-17T16:42:49.120Z?hl=en&inv=1&invt=AbsSoQ&project=open-targets-genetics-dev) for a reference.

> [!TIP]
> By default the google cloud batch installs the Cloud Ops Agent with [`AllocationPolicy.instances.installOpsAgent`](https://cloud.google.com/batch/docs/create-run-job-ops-agent). This ensures that all available metrics in [`etc/google-cloud-ops-agent/config.yaml`](https://cloud.google.com/stackdriver/docs/solutions/agents/ops-agent/configuration) are reported to the Metrics service.

> [!WARNING]
> Currently specifying the `TaskSpec.Runnable.Container` does not install Cloud Ops Agent correctly - one should use the `TaskSpec.Runnable.Script` instead to profile the job.


## CARMA Profiling runs

This profiling was done on gentropy 2.2.0 version running carma implementation in the SusieFineMapper step. The aim was to collect metrics for:

* cost
* CPU usage
* memory usage
* disk usage

reported during the batch task.

### Test data preparation

The test data for the jobs was created for **6 different input combinations**.

```bash
$gcloud storage ls 'gs://ot_orchestration/profiling/carma_ukb_ppp/*'

# fine-mapping manifests.
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/:
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/1000_largest.csv
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/1000_sample.csv
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/100_largest.csv
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/100_sample.csv
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/10_largest.csv
gs://ot_orchestration/profiling/carma_ukb_ppp/finemapping_manifests/10_sample.csv


# input datasets described in the fine-mapping manifests.
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/:
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/1000_largest/
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/1000_sample/
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/100_largest/
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/100_sample/
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/10_largest/
gs://ot_orchestration/profiling/carma_ukb_ppp/loci/10_sample/

```

The data was generated by limiting the N credible sets from `ukb_ppp_eur_data` dataset and filtering the `locus breaker` results by the *lead variantId*.

> [!NOTE] Task size
> The tasks size can be smaller then the expected size due to the StudyLocusId mismatch between fine-mapping and locus breaker!

To run the profiling one need to submit the google batch job via the `run_batch.py` script.

The script submits the google batch job tasks that run the `carma_finemapping.sh` script. This script needs to be uploaded (from the repository root) by using

```bash
make send-carma-finemapping-script
```

To run the script and submit batch job:

```bash
uv sync --frozen
uv run profiling/carma/run_batch.py -m $Input_manifest -s gs://ukb_ppp_eur_data/study_index
```

> [!TIP]
> To run the script one need to set up the application-default-credentials with
>
> ```bash
> gcloud auth login application-default-credentials
> ```
>
> This tep is required to read the manifest and extract the amount of environments needed to be build to start the google batch job and submit the batch job through the python API.

The command will create a google batch job with respect to the input manifest and track the metrics via the [Google Cloud Ops Agent](https://cloud.google.com/stackdriver/docs/solutions/agents/ops-agent).


The collected metrics are listed in the [`CARMA dashboard`](https://console.cloud.google.com/monitoring/dashboards/builder/e87aa472-e2ec-46d0-8218-fea6385f3bfc;filters=type:umlabel,key:benchmark,val:100-sample;startTime=2025-03-17T16:19:39.846Z;endTime=2025-03-17T16:42:49.120Z?hl=en&inv=1&invt=AbsSoQ&project=open-targets-genetics-dev) for a reference.
